Absolutely. The clean way to think about Acquit.ai is as one large platform with two distinct architectural planes:

1. The Acquit.ai Legal AI Platform — the actual product: case workspace, AI legal team, law library, RAG, documents, court integrations, user controls, etc.
2. Schema Studio — the developer/admin visualization and deployment layer that lets you inspect the underlying database architecture and deploy the static studio through IPFS.

8. IPFS Architecture

This is where we keep the distinction we just discussed.

IPFS is not the primary database.

Instead:

                    ACQUIT STORAGE
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
       PostgreSQL                IPFS
       System of Record          Content Addressing
             │                       │
             │                  Public/Immutable
             │                  Legal Resources
             │                  Published datasets
             │                  Source snapshots
             │                  Integrity artifacts
             │
             ▼
       Private Object Storage
       User Documents
       Sensitive Evidence
       Case Files

For sensitive case material, the default should be private encrypted object storage, not public IPFS.

IPFS can store the content-addressable/public side where appropriate.

                 ┌─────────────────────────┐

That is the architecture I would treat as the canonical Acquit.ai blueprint: PostgreSQL is the authoritative application/database layer; pgvector powers RAG; object storage handles private case material; IPFS handles appropriate public/content-addressed artifacts; Schema Studio is a separate static developer-facing application that can itself be deployed through IPFS.
